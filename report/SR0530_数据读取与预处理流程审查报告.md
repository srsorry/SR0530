## 二、脚本功能拆解

### 2.1 DataRead.py —— 原始数据入口

**核心功能**：
1. **读取原始 CSV**：从 `srx-ao-slo/` 和 `Normal/` 目录读取患者微观数据 CSV。
2. **提取基础信息**：
   - 患者姓名、图像编号（Patient ID）、眼别（Eye）
   - 性别（1=男，0=女）
   - **年龄计算**：从文件名提取检查日期（正则 `\d{4}-\d{2}-\d{2}`），减去生日得到年龄。
   - 来源分类：文件名含 `normal` → Source_Class=0，否则=1。
3. **44 ROI 水平展开**：将每个 ROI 的血管占比、细胞密度、细胞间距、离散度、规则性展开为 44 列。
4. **缺失 ROI 检查**：预期 1-44，缺失的填充 NaN 并打印警告。
5. **读取眼轴数据**：从 `AxialLength/*.csv` 读取眼轴、角膜曲率、前房深度、等效球镜。
6. **合并与诊断**：按 `[Patient ID, Eye]` 左外连接，诊断未匹配数据，**最终返回内连接结果（matched）**。

**输出**：`orgData.csv`（宽表，1 行 = 1 只眼）

---

### 2.2 DataCheck.py —— 数据清洗与统计

**核心功能**：
1. **生成基线统计表**：按 Normal vs ASO 分组，统计眼别、性别、年龄、AL、K、ACD、SE 的均值±标准差。
2. **生成 11 个距离数据集**：
   - 距离公式：`distance_mm = 1.0 + k * 0.5`（k=0..10）
   - ROI 映射：每个距离对应 4 个象限的 ROI：`[k+1, k+12, k+23, k+34]`
   - **质量控制**：血管占比 `<= 0.25` 才纳入，计算 4 象限平均值。
   - **单位修复**：角膜曲率 / 前房深度 `< 0.1` 时乘以 1000（米 → 毫米转换）。
3. **数据清洗（clean_data）**：
   - 使用 **6 个基线特征**作为"生理指纹"：`[AL, Age, SE, Gender, CC, ACD]`（保留 4 位小数）。
   - **全局黑名单**：任意 ROI 的 Angular Density > 7000，该患者全局剔除。
   - 生成连续 Subject_ID：`Eye_001` 到 `Eye_N`。
   - 添加 `Eccentricity (mm)` 和 `Subject_ID` 列。

---

### 2.3 gen_44ROIData.py —— 44 个 ROI 独立文件生成

**核心功能**：
- 与 DataCheck.py 的 `clean_data()` 逻辑高度相似，但输出格式不同。
- 将宽表拆分为 **44 个独立的 data{1-44}.csv** 文件。
- 每个文件包含：
  - 基础信息：Subject_ID, Eye, Eccentricity, Quadrant, ROI_Number
  - 眼轴参数：AL, Age, SE, Gender, CC, ACD, RMF
  - 微观指标：Linear/Angular Density, Spacing, Dispersion, Regularity, Blood Vessel Ratio
- **同样的黑名单机制**：Angular Density > 7000 全局剔除。
- **同样的单位修复**：CC / ACD < 0.1 时乘以 1000。

**输出**：`CleanDataRoi/data{1-44}.csv`（被所有 ML 分析脚本直接读取）

## 三、关键逻辑审查

### 3.1 患者唯一标识（生理指纹）

```python
def get_patient_signature(row):
    return (
        round(row.get('Axial length (mm)', 0), 4),
        row.get('Age', 0),
        row.get('Spherical equivalent refraction (D)', 0),
        row.get('Gender', 0),
        round(row.get('Corneal curvature (mm)', 0), 4),
        round(row.get('Anterior chamber depth (mm)', 0), 4)
    )
```

**审查意见**：
- 使用 6 个基线特征的组合作为唯一标识，在数据清洗阶段生成 `Subject_ID`。
- `round(..., 4)` 可能导致精度丢失：如果两名受试者的 AL 在第 5 位小数有差异（如 24.12345 vs 24.12346），会被视为同一人。
- **风险**：如果数据中存在测量误差或录入精度差异，可能导致错误合并或错误剔除。
- **建议**：如果原始数据中有更稳定的唯一标识（如 Patient ID 或图像编号），应优先使用，而非依赖生理特征的组合。

---

### 3.2 异常值剔除（黑名单机制）

```python
# gen_44ROIData.py & DataCheck.py
for roi in range(1, 45):
    ang_col = f'Angular_Cone_Density_ROI_{roi}'
    if pd.notna(row.get(ang_col)) and row.get(ang_col) > 7000:
        blacklist_signatures.add(sig)
        break
```

**审查意见**：
- **阈值 7000**：与之前分析脚本中提到的 >6100 剔除标准不一致。
- **全局剔除逻辑**：如果一只眼的**任意一个 ROI** 的角密度 > 7000，**整只眼**（所有 ROI）被剔除。
- **影响**：这可能导致样本量损失。如果 7000 是合理的异常值阈值（如设备误差或血管遮挡误判），全局剔除是保守的；但如果只是某个 ROI 的局部异常，全局剔除可能过于激进。
- **建议**：记录被剔除的患者数量和原因，在论文 Methods 中明确报告。

---

### 3.3 单位转换逻辑

```python
r1_val = row.get('Cornea curvature (mm)', np.nan)
if pd.notna(r1_val) and r1_val < 0.1:
    r1_val = r1_val * 1000.0

acd_val = row.get('Anterior chamber depth (mm)', np.nan)
if pd.notna(acd_val) and acd_val < 0.1:
    acd_val = acd_val * 1000.0
```

**审查意见**：
- **逻辑**：假设原始数据可能是米（如 0.0078 m），转换为毫米（7.8 mm）。
- **风险**：如果原始数据中存在脏数据（如 0.05，单位不明），会被错误转换为 50。
- **更稳健的做法**：
  ```python
  if pd.notna(r1_val) and r1_val < 1.0:  # 角膜曲率正常范围 6-9 mm
      r1_val *= 1000.0
  ```
- 或者：在 DataRead.py 阶段就统一单位，避免下游脚本反复处理。

---

### 3.4 血管占比阈值

```python
if (bvr_col in row and pd.notna(row[bvr_col]) and row[bvr_col] <= 0.25) and pd.notna(row.get(den_col)):
```

**审查意见**：
- 阈值 0.25（25%）是合理的，与之前分析脚本中的 `bvr <= 0.25` 一致。
- 但需要注意：在 `DataRead.py` 的注释中明确说明 **"根据上一步要求，不进行血管占比剔除，保留所有数据"**，这意味着血管剔除是在 DataCheck.py / gen_44ROIData.py 阶段执行的，而非原始数据读取阶段。
- **一致性**：所有下游脚本（LMM + ML）都使用 `bvr <= 0.25` 作为质量控制标准，这是统一的。

---

### 3.5 年龄计算逻辑

```python
# DataRead.py
date_match = re.search(r'(\d{4}-\d{2}-\d{2})', os.path.basename(file_path))
exam_date = pd.to_datetime(date_match.group(1)) if date_match else pd.Timestamp.now()
```

**审查意见**：
- 从**文件名**提取检查日期，假设文件名格式包含 `YYYY-MM-DD`。
- **风险**：如果文件名格式不一致（如使用下划线、或无日期），`exam_date` 会 fallback 到当前时间，导致年龄计算完全错误。
- **建议**：增加断言检查，确保 `date_match` 不为 None；如果文件名不可靠，应从 CSV 文件内部提取日期（如 `检查日期` 列）。

### 3.6 合并策略（DataRead.py）

```python
# merge_and_diagnose 返回的是 matched（内连接结果）
return matched
```

**审查意见**：
- `merge_and_diagnose` 函数执行的是 `how='outer'` 外连接，用于诊断未匹配数据。
- 但**最终返回的是 `matched`**（即内连接结果），这意味着：
  - 有 AO-SLO 数据但缺少眼轴数据的患者 → **被丢弃**
  - 有眼轴数据但缺少 AO-SLO 数据的患者 → **被丢弃**
- **影响**：如果眼轴数据录入不完整，会导致样本量损失。建议检查被丢弃的患者数量，确认是否为系统性缺失（如某一批次数据未录入眼轴）。
- **论文要求**：在 Methods 中报告最终纳入分析的样本量，以及排除原因。

## 四、与分析脚本的衔接问题

### 4.1 Subject_ID 的生成与反向映射

**生成流程**（DataCheck.py / gen_44ROIData.py）：
```
6 个生理特征 → 生理指纹 → 排序 → Eye_001, Eye_002, ...
```

**反向映射流程**（分析脚本，如 SR_ML_task2.py）：
```python
# 分析脚本中：CleanDataRoi 的 Eye_xxx → orgData.csv 的 Patient ID → Subject_ID
for _, row in df_ref.iterrows():  # df_ref = CleanDataRoi/data1.csv
    eye = row['Eye']
    al = row['Axial length (mm)']
    age = row['Age']
    se = row['Spherical equivalent refraction (D)']
    gender = row['Gender']

    mask = (df_org['Eye'] == eye) & \
           (df_org['Axial length (mm)'] == al) & ...
    # 匹配到 Patient ID，再映射到 Subject_ID
```

**问题**：
- 分析脚本在**反向追溯** Subject_ID 的生成过程，这本身就是脆弱的（浮点数匹配、多字段联合）。
- 如果 DataCheck.py / gen_44ROIData.py 在生成 `Eye_001` 时使用了 `round(..., 4)`，而分析脚本在反向匹配时使用了原始精度，可能导致匹配失败。
- **建议**：在生成 `CleanDataRoi` 文件时，直接保留 `Patient ID` 列，避免后续反向映射。

### 4.2 数据格式一致性

| 维度 | DataCheck.py（11 距离文件） | gen_44ROIData.py（44 ROI 文件） | 分析脚本期望 |
|------|---------------------------|-------------------------------|-------------|
| 文件数量 | 11（data0-10.csv） | 44（data1-44.csv） | 44（部分脚本）或 11（部分脚本） |
| 每文件行数 | 约 48 患者 × 1 行（4 象限平均） | 约 48 患者 × 1 行（单 ROI） | — |
| Eccentricity 列 | 有（clean_data 添加） | 有 | 有（ML 脚本读取） |
| Quadrant 列 | 无 | 有 | 部分脚本使用 |
| ROI_Number 列 | 无 | 有 | 无 |
| Subject_ID 格式 | Eye_001 | Eye_001 | Eye_001 |

**关键发现**：
- `SR_integrated_analysis.py` 的 `load_distance_data()` 函数读取 44 个文件，按 `Eccentricity (mm)` 分组聚合为 11 个距离组。
- 这意味着：gen_44ROIData.py 生成的 44 个文件，在分析脚本中会被**重新聚合**为 11 个距离组。
- 而 DataCheck.py 已经直接生成了 11 个距离文件（4 象限已平均），但分析脚本**没有使用**这些文件，而是重新从 44 个 ROI 文件聚合。
- **冗余**：DataCheck.py 的 `generate_11_distance_datasets()` + `clean_data()` 流程可能是冗余的，分析脚本完全可以直接读取 DataCheck.py 预聚合的 11 个文件，节省计算时间。

## 五、发现的问题与风险

### 🔴 高风险

| 问题 | 影响 | 位置 |
|------|------|------|
| **分析脚本的反向映射（eye_to_pid）** | 浮点数 `==` 匹配可能导致错误映射或匹配失败 | 所有 ML 脚本 |

### 🟡 中风险

| 问题 | 影响 | 位置 |
|------|------|------|
| **get_patient_signature 的 round(..., 4)** | 精度丢失可能导致错误合并或错误剔除 | DataCheck.py, gen_44ROIData.py |
| **年龄计算依赖文件名格式** | 文件名格式不一致时年龄计算错误 | DataRead.py |
| **单位转换逻辑（< 0.1 时 ×1000）** | 脏数据可能被错误转换 | DataCheck.py, gen_44ROIData.py |
| **Angular Density > 7000 全局剔除** | 阈值与之前提到的 >6100 不一致；全局剔除可能过于激进 | DataCheck.py, gen_44ROIData.py |
| **add_angular_density 未审查** | 角密度计算的正确性无法确认 | DataCheck.py（依赖外部模块） |

### 🟢 低风险

| 问题 | 影响 | 位置 |

## 六、修复建议

### 6.1 数据映射层（最优先）

**问题**：分析脚本中的反向映射过于脆弱。

**方案 A（推荐）**：在生成 CleanDataRoi 时直接保留 Patient ID
```python
# 在 gen_44ROIData.py 中，生成 records 时添加：
records.append({
    'Patient_ID': row.get('Patient ID', np.nan),  # 直接从 orgDataWithAng 传递
    'Subject_ID': subject_id,
    ...
})
```

**方案 B**：在分析脚本中改用 `np.isclose` 匹配
```python
# 分析脚本中
mask = (df_org['Eye'] == eye) & \
       np.isclose(df_org['Axial length (mm)'], al, rtol=1e-5) & \
       np.isclose(df_org['Spherical equivalent refraction (D)'], se, rtol=1e-5) & ...
```

| 数据流 | 用途 | 建议 |
